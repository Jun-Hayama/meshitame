## 15章のねらい

- 体重は1日で±1〜2kgくらい水分で動く。1ヶ月1kgペースだと1週間で0.25kgなので、日ごとの数字では減っているかどうかわからない
- だから「体重ではなく行動を見て、ちゃんとやっていれば大丈夫」と伝える。体重が上がった日に、気にしなくていいと言ってあげる
- あわせて「◯月のメシため」カードの文字を減らし、チート名の羅列をやめて kcal で見せる
- 「ゼロカロ化」という言葉は使わない。トーストと同じ「なかったことに」にそろえる

## 15.1 「順調」の判定（lib/calories.ts）

- 順調 = 今月の貯まったpt ≧ ペースの目印、かつ 貯まったpt > 0
  - ペースの目印 = 目標 × 今日が何日目か ÷ 月の日数（既存の calcMeshipoGauge の pacePt と同じ。四捨五入）
  - チートが未登録で目標が0の月は、貯まったpt > 0 なら順調
- 純粋関数にしてテストを付ける（例：`isOnPace({ targetPt, earnedPt, dayOfMonth, daysInMonth })`。既存の calcMeshipoGauge の onPace を使ってもよい）
- 順調でないときに「遅れています」「足りません」のような言葉は出さない。何も足さないだけ

## 15.2 今日の画面：今週の行

- 順調のときは「今週 +825pt ・ 順調です」にする（「 ・ 順調です」は text-amber-400）
- 順調でないときは今までどおり「今週 +825pt」だけ
- 日曜・月曜の振り返り文に置き換わっているときは、何も足さない（今までどおり）

## 15.3 体重：上がった日のひと言（トースト）

- 体重を保存した直後（ホームの今朝の体重・体重タブのどちらからでも）、次の両方を満たすときだけトーストを出す
  1. 保存した体重が「その日の前日までの7日間の記録の平均」より 0.5kg 以上高い（前日までの7日間に記録が3件以上あるとき。その日の記録は平均に含めない）
  2. 15.1 の順調
- 文言：「日ごとの上下は水分です。メシためが続いているので、このままで大丈夫。」
- 既存の Toast を使い、文が長いので表示時間は 4000ms 程度にする。体重タブには今 Toast がないので追加する
- 判定は純粋関数にしてテストを付ける（例：`shouldShowWeightReassurance({ logs, date, weightKg, onPace })`。しきい値 0.5kg は lib/calorieConstants.ts に定数で置く）
- 体重タブで順調を判定するのに必要なデータ（今月のメシため・うごための記録）が足りなければ、今日の画面と同じ取り方で読み込む
- 毎日は出さない。上の条件のときだけ

### 3週続けて増えているとき（体重タブ）
- 前週比（calcWeekOverWeek）が、今日・7日前・14日前の3回続けて 0.1kg 以上の増（四捨五入で「0.1kg増」以上）、かつどれも参考値でないとき、「このところ」の欄の下に1行出す：
  「3週続けて少しずつ増えています。必要量が高めかもしれません」＋「設定を見直す」リンク（/setup へ）
- このときは 15.3 のトーストは出さない
- 判定は純粋関数にしてテストを付ける

## 15.4 「◯月のメシため」カードをシンプルにする

### 見出し（describeZeroCalHeadline を置き換え）
チート名の羅列をやめて、kcal で見せる。数字は3桁区切り（3,950）。

| 状態 | 見出し | 色 |
|---|---|---|
| チートが未登録 | 「食べたいものを先に決めよう」（今までどおり） | 今までどおり |
| 貯まったpt = 0 | 「今月のチート 3,950kcal」 | stone-200 |
| 途中（0 < 貯まったpt < 目標） | 「3,120kcal、なかったことに。」（3,120 = zeroedPt） | amber-400 |
| 全部（貯まったpt ≧ 目標） | 「3,950kcal、ぜんぶなかったことに。」 | amber-400 |

- 見出しの数字は 0kcal化済みのチートの件数ではなく、kcal（= zeroedPt）で出す
- チート名は内訳（タップで展開）にだけ出す。内訳の一覧は今までどおり

### ゲージの下の行
- 「ゼロカロ化 ◯ / ◯kcal」の行と「・あとメシため◯回で{チート名}も0kcal」の行は消す
- 貯まったpt = 0 のとき：「メシためで、なかったことにしていこう」（stone-500）
- 途中のとき：「あと 830kcal」（stone-400。830 = 目標 − 貯まったpt）
- 全部のとき：ごほうびの行（下）

### ごほうびの行
- 1行にまとめる：「ごほうび 460kcal ・ ショートケーキまでいけます」
  - 150kcal未満で品名がないときは「ごほうび 460kcal」だけ
  - 全体を amber-200 にする（「 ・ 」と品名の部分は stone-300 でもよい）
- **ごほうびがゲージのはみ出した部分のことだと、見てわかるようにする**
  - 行の頭に、ゲージのはみ出し部分と同じ色・形の小さな丸い棒（例：`inline-block w-3 h-1.5 rounded-full bg-amber-200 mr-1.5 align-middle`）を置く
  - ゲージのはみ出し部分（amber-200）とテキストの色をそろえる
- ごほうびが0のときは行を出さない（今までどおり）

### ゲージの上の絵文字
- まとめたあとのアイコンが5個以下なら、今までどおり
- 6個以上になるときは、アイコンを1つだけにする：
  - 位置：ゲージの0kcal化済みの位置（zeroedPt ÷ 目盛りの最大）
  - 中身：0kcal化済みのチートの中でいちばん多い絵文字 ×0kcal化済みの件数（例「🍺×13」）
  - 0kcal化済みが0件なら、アイコンは出さない
- buildGaugeMarkers に上限を足すか、別の関数にする。上限5は定数で置き、テストを付ける

### 「タップで内訳」
- 文字の「タップで内訳」は消して、カードの右下に小さな「›」（stone-600）を置く。開いているときは「⌄」か回転させる
- 開いたときの「閉じる」は今までどおり

### 変えないもの
- トースト「{チート名}、なかったことに。」（新たに0kcal化済みになったとき）
- 体重の一言「これだけ食べて、月初めから0.4kg減」
- 内訳の中身と「記録を見る・直す」
- ゲージの色（目標まで amber-400、その先 amber-200）

全部のとき：
