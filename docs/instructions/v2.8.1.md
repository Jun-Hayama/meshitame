## 1. カード「◯月のチート」：ヒントを「あと◯kcal」の横に置く
- 一番下の行（`describeCardWayLine` の行）をなくします。「どうやって届く？ ヒント ›」も「🚶 30分歩けば、なかったことに［記録する］ヒント ›」も出しません。
- 代わりに、「貯めた」の行の右端、「あと945kcal」のすぐ右に「**ヒント ›**」を置きます。
  - 出すのは「あと◯kcal」が出ているとき（`bar.kind === 'short'` で、`buildCheatHints` が null でないとき）だけです。なかったことにできたら、「あと◯kcal」と一緒に消えます。
  - 見た目：amber-400、text-xs、太字。`InnerButton` を使い、押すとヒントのシートを開きます（カード全体の「ログへ」より優先）。
  - 押せる範囲は文字より少し広めにします（上下に余白をとる、など）。
- 横幅が足りないときは、左の「🐷31回 🏃11回」が今と同じく省略（truncate）されるようにして、「◯kcal」「あと◯kcal」「ヒント ›」は折り返さず必ず見えるようにしてください。幅375pxで確認してください。
- 予定の行（「28日の焼肉まで、あと450kcal」）は今のままです。

## 2. ヒントのシート：カードの一番下の行でやっていたことを中に入れる
- 見出し「あと◯kcal」のすぐ下に、まだの分が `EASY_WALK_MAX_KCAL`（300kcal）以下のときだけ、次の1行を出します。
  - 「🚶 30分歩けば、なかったことに」＋［記録する］（amber のボタン）
  - 分数は今の `describeCardWayLine` と同じ計算（`EASY_WALK_STEP_MINUTES` で切り上げ）です。
  - ［記録する］を押したら、シートを閉じて、今のカードの［記録する］と同じ動き（うごための画面をウォーキング・その分数で開く）にします。
- `describeCardWayLine` は、300kcal以下の行だけを返す関数 `describeEasyWalkLine(pendingKcal)`（`{ text, walkMinutes } | null`）に直してください。300kcalを超えるときと0以下のときは null です。「どうやって届く？」の文言は消します。
- 回数・時間・歩数の表と「ちょっとしたコツ」は今のままです。

## 3. うごため：4つのボタンを固定で並べる
- 今日の記録の「🏃 うごため」のボタンを、次の5つに固定します（いつものうごため2つを履歴から選ぶ仕組みはやめます）。
  - 🚶 ウォーキング・🏃 ランニング・💪 筋トレ・⚽ スポーツ・［＋］
- ボタンの文字は「**アイコン＋時間**」だけにします（例：「🚶45分」）。種類名は出しません。kcal も出しません（トーストで伝える）。
  - 時間は、設定画面でセットした時間（4章）です。セットしていなければ30分です。
  - 読み上げ用に `aria-label`（例：「ウォーキング 45分を記録」）をつけてください。
- 5つは1行に並べます（`grid grid-cols-5` など、同じ幅）。文字は折り返さないでください。幅375pxで「🚶120分」が入りきらないときは、そのボタンだけ文字を少し小さくしてください。
- ［＋］は、ほかの4つと区別がつくように枠の色を変えます（例：4つは bg-stone-800 ＋ amber の文字、［＋］は枠線だけ）。押すと今の［＋ ほかのうごため］と同じく、うごための画面を開きます（時間を変えたいとき・自転車・歩数はここから）。
- 4つを押したときの動きは今の `saveQuickExercise` と同じです。その場で保存して、トースト（`describeRecordToast`）と［取り消す］（5秒）を出します。2回押したら、セットした時間の記録がもう1件増えます。
- 小見出し「🏃 うごため　意識して動いた分」と枠、「今日は 🚶30分・👣8,000歩」の行は今のままです。過去の日を見ているときは、その日に記録されるのも今のままです。
- 使わなくなる `pickFrequentExercises`・`FREQUENT_EXERCISE_DAYS`・`FREQUENT_EXERCISE_MAX`・`FREQUENT_EXERCISE_DEFAULTS` と、そのテストは消してください。

## 4. 設定画面：うごための時間
- 設定画面の「減らすペース」の下に、カードを1枚足します。

```
うごための時間
今日の画面のボタンを押したときに記録する時間です
🚶 ウォーキング   ［45分 ▾］
🏃 ランニング     ［30分 ▾］
💪 筋トレ         ［15分 ▾］
⚽ スポーツ       ［60分 ▾］
```

- 選べる時間：15分〜120分、15分刻み。最初はすべて30分。
- 選んだらすぐ保存します（保存ボタンはなし）。保存に失敗したら、減らすペースと同じ形で赤い文字を出して、元の値に戻します。
- 読み書きは `lib/reducePace.ts` と同じ形で、新しく `lib/exercisePresets.ts` を作ってください（`useExercisePresets(userId)`・`saveExercisePresets(userId, presets)`。今日の画面と設定画面で使う）。`user_profiles` の主キーは `id` なので upsert は `onConflict: 'id'` です。
- 読み込みに失敗したとき（行がない・列がまだない）は、すべて30分として動かします。今日の画面はエラーを出さずにボタンを出してください。

## 6. マイグレーション（`migration_v2_8_1_exercise_presets.sql`）
- `migration_v2_4_reduce_pace.sql` と同じ形で、何度実行しても大丈夫なように書いてください。

```sql
alter table user_profiles
  add column if not exists exercise_presets jsonb not null
  default '{"walking":30,"running":30,"weights":30,"sports":30}'::jsonb;
```

- 既存の行は既定値（すべて30分）になり、ほかの列は変えません。
- RLS（`users_own_data`：`auth.uid() = id`）がなければ作り、`authenticated` に select / insert / update を grant してください（v2.4 と同じ）。
- 値のチェックは画面側（`normalizeExercisePresets`）で行うので、DBの check 制約は不要です。
