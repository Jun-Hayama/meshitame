# メシため v2 仕様（シンプル化アップデート）

## 背景と方針

- v1は表示・管理が細かすぎて継続できなかった
- コア価値「食べたい・飲みたいを先に入れる → それでも痩せていけるのが見える」は残す
- 毎日の記録と表示を極限まで軽くする
- 計算・判定はすべてロジックで行い、AIは相談機能のみに限定する
- 友達との共有機能はv2では作らない（まず自分が続けられる状態を作る）

## 1. 欲望の登録（月単位）

- 月の中で決まっている予定を日付指定で登録（例：◯日 飲み会、◯日 ラーメン）
- 頻度ベースの欲望も登録（例：お酒は週3回、ラーメンは週1回）
- 月の途中で追加する場合も、いつでも1タップで追加できる
- 欲望（★）は削らない。手段側で吸収する思想は維持

## 2. 1日の目安（固定パターン）

- 朝・昼・夜それぞれに和・洋の2パターンを事前定義（AI生成しない）
- 品数とカロリーをセットで表示
  - 例：朝・和「ご飯一膳、目玉焼き、サラダ、味噌汁 ≒ 400kcal」
- パターンの合計は、その人の1日の目安カロリーに合うよう量を調整して表示する

## 3. 毎日の記録（3秒で終わる）

- 各食事を目安に対して3択で記録：控えめ / 目安どおり / がっつり
- 「食べすぎ」という言葉は使わない
- 差分は固定値（6-3参照）

## 4. 運動はアドオン（メシポイント）

- 運動を前提にプランを組まない
- 運動・散歩をやった日に任意で追加すると、メシポイントが貯まる
- 1pt = 1kcal（カロリーと完全連動）

## 5. ホーム画面に出すもの

- 今日の目安パターン（和/洋）
- 今週の欲望ごとの貯金ゲージ（例：★ラーメンまで 300/450kcal・あと軽め1回分）
- 今週の軽め 1/3回
- 7日平均の体重とゲートまでの進捗
- 次の欲望の予定（「◯日は飲み会！」）

## 6. 計算ロジック（すべて決定的・純粋関数）

- 1日の目安カロリー = TDEE − 1日の貯金kcal（6-2で算出）
- 欲望のコストは固定値テーブルで管理（6-3）
- 計算は月単位で行う（月の目標・メシポゲージは月で1本。10-4・11-3）。週の予算・週の区切りは使わない
- 体重換算 = 7200kcal/kg
- 欲望用の貯金：目安パターンの合計は「1日の目安カロリー − 150kcal」で作る。目安どおりに食べると1日150kcal、週1050kcalが欲望用に貯まる（WANT_BUFFER_PER_DAY = 150）
  - 週の欲望貯金 = 150 × その週の日数。減量用の1日の貯金（6-2）は欲望に使わない
  - 目安パターンの合計は基礎代謝を下回らない。つまり1日の貯金の上限 = min(750, TDEE − 基礎代謝 − 150)

## 6-2. 目標設計とゲート

**初回設定と上限チェック**

- 初回設定で身長・現体重・目標体重・期間・年齢・性別を入力する
- BMIと標準体重（BMI22）は参考として表示する
- 年間の減量上限はBMIで変える（アプリ独自ルール、日本肥満学会ガイドライン「3〜6ヶ月で3〜10%」から保守的に設定）
  - BMI25未満：年5%
  - BMI25〜35：年15%
  - BMI35以上：年20%
- 上限を超える場合は期間延長を提案する
- 期間は3ヶ月単位。年の上限は「年の上限 × 期間の月数 ÷ 12」で按分する
- ゲートは3ヶ月ごと。4ゲート（12ヶ月）は35/30/20/15%、それ以外の数は当面均等配分
- 例：178cm・104kgはBMI約32.8なので、年15kg（約14%）は上限内
- ゲート1の最低ラインは「3ヶ月で現体重の3%」
- 1日の貯金は最大750kcal、摂取目安は基礎代謝を下回らないようにする
- 持病がある人向けに「気になる人は医師に相談」の一言をアプリ内に表示

**ゲート（3ヶ月ごと×4回）**

- 年間目標を前半多めに配分：35% / 30% / 20% / 15%
- 例：104kgで年15kg → ゲート1 −5.25kg、ゲート2 −4.5kg、ゲート3 −3.0kg、ゲート4 −2.25kg

**毎月の計算**

- 月の目標kg = ゲート目標 ÷ 3
- 1日の貯金kcal = 月の目標kg × 7200 ÷ その月の日数

**月末の見直し**

- 7日平均の実績体重から残りの目標を再計算し、残り月で均等に割り直す
- 割り直しで上限750kcal/日を超える場合は、ゲートの期限を後ろ倒しにする

## 6-4. 貯金ゲージ・軽め回数・マイナス時

**軽めは「週の回数目標」で置く**

- 特定の日を軽めの日に指定しない
- 軽めの回数 = 切り上げ((その週の欲望コスト − その週の貯金 − 運動ポイント) ÷ 150)
- 例：飲み会1回＋ラーメン1回 = 1500kcal、週の貯金が1050kcal → 不足450kcal → 軽め3回
- 朝・昼・夜のどれで消化してもよい
- 上限は週7回。超える場合は運動か、欲望をずらすことを提案する

**表示は「貯金ゲージ」**

- 週のはじめに欲望ごとの貯金ゲージを0から表示（例：★ラーメンまで 0/450kcal）
- 軽め（+150）・運動（+pt）でゲージが増える
- 満タンで「★達成！」。超えた分はボーナスとして次の欲望・翌週へ持ち越す
- 内部計算は「不足から0を目指す」と同じだが、見せ方は常に貯める方向

**マイナス時は自分で選ぶ**

- マイナス表示は、がっつりなどで計画より多く食べ、取り戻しが必要なときだけ
- 欲望の予定は自動で動かさない
- 「このままだとゲートに少し届かないペース」と事実だけ伝える。責める言葉は使わない
- 解消方法を数字つきで並べ、ユーザーが選ぶ
  - 運動で取り戻す（例：ウォーキング2回 = 300pt）
  - 食事を軽めにする（例：軽め4食 = 600pt）
  - 欲望を通常の食事に変える（例：ラーメン → 普通の食事 = 500pt）

**体重は毎朝はかる**

- 毎朝記録。メインは7日間の平均、当日の数字は小さく表示
- 進捗判定と月末の割り直しには7日間の平均を使う

## 7. AIの役割（相談のみ）

- 体重が動かない時のチェックイン相談
- 自由な質問への相談窓口
- プラン生成・リプラン・レコメンドはAIを使わない

## 8. v1から削るもの

- 細かい食事・運動ブロックの表示
- 運動前提の週間プラン
- AIによるプラン生成（/api/generate-plan）とリプラン（/api/replan）
- 週次の欲望宣言フロー

## 9. 実装の順番

**フェーズ1：毎日使える状態にする**

1. 計算ロジック（目標・ゲート・週予算・貯金ゲージ・軽め回数）を `@/lib/calories` に集約し、テストを書く
2. 初回設定（身長・体重・目標・期間 → BMI上限チェック → ゲートと1日の貯金を算出）
3. 欲望の月登録（日付指定＋週の頻度、いつでも1タップ追加）
4. 毎日の記録とホーム（目安パターン表示・3択記録・貯金ゲージ・軽めの回数）

**フェーズ2**

1. 運動アドオン（1pt = 1kcal でゲージに加算）
2. 毎朝の体重記録と7日間の平均
3. 月末の割り直し
4. 進捗チャート（7日平均の体重とゲート目標ラインを重ねて表示）

**フェーズ3**

1. AI相談（体重が動かない時のチェックイン・自由相談）

## 10. v2.1 変更（2026-11-08 追加）

### 10-1. 名前の変更
- 「欲望」→「チート」（タブ名・画面・文言すべて。コード上の want → cheat への改名は任意。DB列名は変えなくてよい）
- 「欲望ゲージ」「貯金ゲージ」→「メシポゲージ」

### 10-2. 今日の目安：和/洋の切り替えをやめる
- 朝・昼・夜それぞれ「目安 ≒ ◯kcal」だけを表示する（毎日共通。目安パターン合計 = 1日の目安 − 150）
- 各食事に「?」ボタン。押すと次の2つを出す
  - **目安くらいの例**（3〜5個）：その食事の目安kcalに近いメニュー例。和・洋・外食・コンビニを混ぜる
  - **がっつりの例**（3〜5個）：目安 + 300kcal 以上になるメニュー例
- 例は固定のメニュー表（lib/mealExamples.ts）から、目安kcalに近いものを選んで出す（AIは使わない）
  - メニュー表の各項目：名前・kcal・ジャンル（和/洋/外食/コンビニ）・食事（朝/昼/夜）
  - 選び方：目安くらい＝目安の ±15%、がっつり＝目安 + 300 以上。近い順に表示
- 記録の3択（控えめ/目安どおり/がっつり）はそのまま。例を見て自分で判断できるようにする

### 10-3. チートを細かく登録する（複数選択）
- チートは1回ごとに、アイテムを数量つきで自由に組み合わせて登録し、合計kcalを出す（ジャンルをまたいでもよい。例：ラーメン＋ライス＋ビール）
- タイプは2種類
  - **置き換え**：その食事の代わりに食べる（ラーメン、飲み会、焼肉など）→ コスト = 合計kcal − その食事の目安kcal
  - **上乗せ**：食事に追加する（晩酌、スイーツなど）→ コスト = 合計kcal
- 1回のチートのタイプは1つ。初期値は最初に選んだアイテムのジャンルのタイプで、登録時に切り替えられる
- 置き換えのときは、どの食事（朝/昼/夜）の代わりかを選ぶ（初期値は夜）
- 初期アイテムは「10-6. チートアイテム表」を lib/cheatItems.ts に入れる（値はざっくりの目安、あとで調整可）

- アイテムは数量つきで複数選択（例：ビール500ml × 2 ＋ 唐揚げ）
- 登録画面に「このチートは ◯kcal ＝ 軽め◯回 or ウォーキング◯分」と換算を出す
- 頻度ベース（週◯回）の登録も、同じくアイテムを選んで1回分の中身を決める
- 既存の WANT_COSTS は「中身を選ばなかった時のデフォルト」として残す

### 10-4. メシポゲージは「月で1本」
- ゲージは月に1本だけ。チートごとのゲージは作らない
- **目標（貯めるpt）** = その月のチート全部のコスト合計
  - 事前に登録したチートも、当日や途中で追加したチートもすべて含む
  - 頻度ベース（週◯回）は、その月に入る回数分を数える
  - 例：ラーメン700pt × 月4回 = 2800pt → 途中でワイン1本（500pt）の晩酌を追加 → 目標3300pt
- **貯まったpt** = その月の合計で、どの日の分も同じプールに入る
  - 経過した日数 × 150pt（目安どおりで貯まる欲望用の貯金）
  - 軽め1回 +150pt / がっつり1回 −300pt（記録の3択から）
  - 運動のpt
- 表示
  - 「メシポ 1200 / 3300pt」とゲージ1本
  - ペースの目印：今日までに貯まっていたい量 = 目標 × 経過日数 ÷ 月の日数。ゲージ上に線で出し、「ペースどおり」「あと◯ptでペースに追いつく」を表示
  - 今月の残りのチート一覧（日付と中身）。済んだものは「★済み」
- 目標を超えたら「あと◯pt分、追加でチートできる」と表示（超えた分は翌月に持ち越さず、その月の中で使う）
- 声かけは月全体に向ける（例：「今日30分歩くとペースに追いつく」）
- 軽めの回数も月で出す：今月あと必要な軽め = 切り上げ（（目標 − 見込みpt）÷ 150）。見込みpt = 現在の貯まったpt + 残り日数 × 150。0回なら「今月は軽めなしでOK」
- 週ごとの予算（6章の calcWeeklyBudget）はホームの主表示には使わない

### 10-5. 運動の記録（フェーズ2から前倒し）
- ホームから1タップで「運動を追加」→ 種類と時間を選ぶ
- 種類と1分あたりの目安：ウォーキング 5pt/分、ランニング 10pt/分、筋トレ 5pt/分、自転車 7pt/分、スポーツ 7pt/分（ウォーキング30分=150pt など既存値と一致）
- 歩数でも入力できる：1000歩 = 35pt
- 記録はその日の日付で保存し、月のメシポプールに加算する

### 10-7. 過去の日の記録
- 何も記録しなかった日は「目安どおり」として扱う（今の計算のまま：経過日数×150pt が自動で貯まり、記録は軽め/がっつりの差分だけ）
- ホームの日付の横に「‹ ›」を付け、過去の日に切り替えて、その日の食事の3択・運動・チートを記録できる
- さかのぼれるのは7日前まで（今日を含めて8日分）。未来の日には切り替えられない（先の予定はチートのタブから登録）
- 過去の日を表示中は「11/7（土）を表示中」と分かるように出し、「今日に戻る」ボタンを置く
- 記録した日の月のゲージに反映する（月をまたいで前月の日を記録したら、前月の集計に入る）
- 「★チート」の表示（置き換えた食事）も、その日に合わせて出す

## 11. フェーズ2：体重・月の割り直し・進捗チャート（2026-11-08 追加）

### 11-1. 毎朝の体重記録
- ホームの上部に「今朝の体重」入力カードを置き、1タップで入力できる（入力済みなら「今朝 103.2kg ✓」と小さく表示）
- 体重タブ（/weight）を作り直す：入力、記録の一覧、進捗チャート（11-4）
- 1日1件。同じ日に入れ直したら上書きする
- 日付は日本時間。過去の日の記録・修正は10-7と同じく7日前まで
- ウエスト（任意）は残してよいが、目立たせない
- 体重を入れ忘れた日はそのまま空白（補完しない）

### 11-2. 7日間の平均
- 7日平均 = その日を含む直近7日間にある記録の平均（記録がない日は飛ばす）
- 記録が3件未満のときは「参考値」と表示する
- メインに出すのは7日平均。当日の数字は小さく出す
- 前週比（7日平均の差）を「−0.4kg」のように出す。増えたときも責めない言葉にする（例：「水分などで動く範囲です」）

### 11-3. 月の割り直し
- 月が変わって最初にアプリを開いたとき、その月の目標を決めて保存する（月の途中では変えない＝数字が毎日ブレない）
- 決め方（ゲートの前半多めの配分は保つ）
  - その月が属するゲートの「終わりの目標体重」= 開始体重 − そのゲートまでのゲート目標の合計
  - その月の目標kg = （月初の7日平均 − ゲート終わりの目標体重）÷ ゲートの残り月数（その月を含む）
  - 1日の貯金 = その月の目標kg × 7200 ÷ その月の日数（上限は6-2と同じ：min(750, TDEE − 基礎代謝 − 150)）
  - 月初の7日平均 = 前月の最後の7日間（1日の7日前〜前日）の記録の平均。月の何日に開いても同じ値になる
  - 月初の7日平均がない（記録3件未満）ときは、計画どおりの値（calcCurrentMonthTargets）を使う。この場合もその月の値として保存する
- 保存は monthly_targets に1ヶ月1行（goal_plan ごと）。その月に開かなかったときも、あとで開いたときに同じ決め方で作る
- まだ来ていない月（チートのタブで来月を見るときなど）は、仮に計画どおりの値を使う。その月になったら割り直す
- 月の目標の入口は1つ（lib/monthTargets.ts の useMonthTargets）。ホーム・チートのタブ・チートの追加画面はすべてこれを使う
- 初回設定を月の途中でやり直したら、新しい目標の開始月として初回設定の値を使う
- 予定より進んでいるとき：目標kgが0以下なら、その月の1日の貯金は0（維持）。「ペースより先に進んでいます」と表示
- 遅れていて上限に当たったとき（capped）：「このままだとゲートに約◯kg届かないペース」と事実を伝え、選択肢を出す
  - 期間を延ばす（初回設定を延長した期間で開き直す。ボタン1つで /setup に期間を入れた状態で移動）
  - そのまま続ける（翌月の割り直しでまた調整される）
- 体重が目標に達したら、ゲート達成を表示（11-5）
- 開始月（11月）は初回設定の値をそのまま使う

### 11-4. 進捗チャート
- 体重タブに表示。横軸は日付、縦軸は体重
- 線：7日平均の体重
- 点：毎日の体重（薄く小さく）
- 目標ライン：開始日の開始体重から、各ゲートの終わり（3ヶ月ごと）の目標体重を結んだ折れ線（点線）
- ゲートの区切りに縦の目印とラベル（ゲート1〜4）
- 期間の切り替え：1ヶ月 / 3ヶ月 / 全期間
- 今日の位置で「目標ラインより ◯kg 先行／◯kg 後ろ」を表示

### 11-5. ゲート達成
- 7日平均がゲートの終わりの目標体重以下になったら「ゲート◯達成！」を表示（1回だけ）
- 開始体重からの減量が3%・5%に達したら、健康メリットを一言出す（例：3%で「血糖値や中性脂肪の改善が期待できるライン」、5%で「血圧の改善も期待できるライン」）
