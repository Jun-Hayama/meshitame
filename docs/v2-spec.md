# メシため v2 仕様（シンプル化アップデート）

## 背景と方針

- v1は表示・管理が細かすぎて継続できなかった
- コア価値「食べたい・飲みたいを先に入れる → それでも痩せていけるのが見える」は残す
- 毎日の記録と表示を極限まで軽くする
- 計算・判定はすべてロジックで行い、AIは相談機能のみに限定する
- 友達との共有機能はv2では作らない（まず自分が続けられる状態を作る）

## 1. 欲望の登録（月単位）

- 月の中で決まっている予定を日付指定で登録（例：◯日 飲み会、◯日 ラーメン）
- 頻度ベースの欲望も登録（例：お酒は週3回、ラーメンは週1回）
- 月の途中で追加する場合も、いつでも1タップで追加できる
- 欲望（★）は削らない。手段側で吸収する思想は維持

## 2. 1日の目安（固定パターン）

- 朝・昼・夜それぞれに和・洋の2パターンを事前定義（AI生成しない）
- 品数とカロリーをセットで表示
  - 例：朝・和「ご飯一膳、目玉焼き、サラダ、味噌汁 ≒ 400kcal」
- パターンの合計は、その人の1日の目安カロリーに合うよう量を調整して表示する

## 3. 毎日の記録（3秒で終わる）

- 各食事を目安に対して3択で記録：控えめ / 目安どおり / がっつり
- 「食べすぎ」という言葉は使わない
- 差分は固定値（6-3参照）

## 4. 運動はアドオン（メシポイント）

- 運動を前提にプランを組まない
- 運動・散歩をやった日に任意で追加すると、メシポイントが貯まる
- 1pt = 1kcal（カロリーと完全連動）

## 5. ホーム画面に出すもの

- 今日の目安パターン（和/洋）
- 今週の欲望ごとの貯金ゲージ（例：★ラーメンまで 300/450kcal・あと軽め1回分）
- 今週の軽め 1/3回
- 7日平均の体重とゲートまでの進捗
- 次の欲望の予定（「◯日は飲み会！」）

## 6. 計算ロジック（すべて決定的・純粋関数）

- 1日の目安カロリー = TDEE − 1日の貯金kcal（6-2で算出）
- 欲望のコストは固定値テーブルで管理（6-3）
- 週の予算 = 月の残り予算 ÷ 残りの週数（毎週計算し直す）
- 週は月曜始まり（既存の getWeekStart を使う）。月をまたぐ週は、日数で各月に按分する
- 体重換算 = 7200kcal/kg
- 欲望用の貯金：目安パターンの合計は「1日の目安カロリー − 150kcal」で作る。目安どおりに食べると1日150kcal、週1050kcalが欲望用に貯まる（WANT_BUFFER_PER_DAY = 150）
  - 週の欲望貯金 = 150 × その週の日数。減量用の1日の貯金（6-2）は欲望に使わない
  - 目安パターンの合計は基礎代謝を下回らない。つまり1日の貯金の上限 = min(750, TDEE − 基礎代謝 − 150)

## 6-2. 目標設計とゲート

**初回設定と上限チェック**

- 初回設定で身長・現体重・目標体重・期間・年齢・性別を入力する
- BMIと標準体重（BMI22）は参考として表示する
- 年間の減量上限はBMIで変える（アプリ独自ルール、日本肥満学会ガイドライン「3〜6ヶ月で3〜10%」から保守的に設定）
  - BMI25未満：年5%
  - BMI25〜35：年15%
  - BMI35以上：年20%
- 上限を超える場合は期間延長を提案する
- 期間は3ヶ月単位。年の上限は「年の上限 × 期間の月数 ÷ 12」で按分する
- ゲートは3ヶ月ごと。4ゲート（12ヶ月）は35/30/20/15%、それ以外の数は当面均等配分
- 例：178cm・104kgはBMI約32.8なので、年15kg（約14%）は上限内
- ゲート1の最低ラインは「3ヶ月で現体重の3%」
- 1日の貯金は最大750kcal、摂取目安は基礎代謝を下回らないようにする
- 持病がある人向けに「気になる人は医師に相談」の一言をアプリ内に表示

**ゲート（3ヶ月ごと×4回）**

- 年間目標を前半多めに配分：35% / 30% / 20% / 15%
- 例：104kgで年15kg → ゲート1 −5.25kg、ゲート2 −4.5kg、ゲート3 −3.0kg、ゲート4 −2.25kg

**毎月の計算**

- 月の目標kg = ゲート目標 ÷ 3
- 1日の貯金kcal = 月の目標kg × 7200 ÷ その月の日数

**月末の見直し**

- 7日平均の実績体重から残りの目標を再計算し、残り月で均等に割り直す
- 割り直しで上限750kcal/日を超える場合は、ゲートの期限を後ろ倒しにする

| 目安どおり（1食） | ±0 |
| がっつり（1食） | +300kcal |
| ラーメン | +500kcal |

## 6-4. 貯金ゲージ・軽め回数・マイナス時

**軽めは「週の回数目標」で置く**

- 特定の日を軽めの日に指定しない
- 軽めの回数 = 切り上げ((その週の欲望コスト − その週の貯金 − 運動ポイント) ÷ 150)
- 例：飲み会1回＋ラーメン1回 = 1500kcal、週の貯金が1050kcal → 不足450kcal → 軽め3回
- 朝・昼・夜のどれで消化してもよい
- 上限は週7回。超える場合は運動か、欲望をずらすことを提案する

**表示は「貯金ゲージ」**

- 週のはじめに欲望ごとの貯金ゲージを0から表示（例：★ラーメンまで 0/450kcal）
- 軽め（+150）・運動（+pt）でゲージが増える
- 満タンで「★達成！」。超えた分はボーナスとして次の欲望・翌週へ持ち越す
- 内部計算は「不足から0を目指す」と同じだが、見せ方は常に貯める方向

**マイナス時は自分で選ぶ**

- マイナス表示は、がっつりなどで計画より多く食べ、取り戻しが必要なときだけ
- 欲望の予定は自動で動かさない
- 「このままだとゲートに少し届かないペース」と事実だけ伝える。責める言葉は使わない
- 解消方法を数字つきで並べ、ユーザーが選ぶ
  - 運動で取り戻す（例：ウォーキング2回 = 300pt）
  - 食事を軽めにする（例：軽め4食 = 600pt）
  - 欲望を通常の食事に変える（例：ラーメン → 普通の食事 = 500pt）

**体重は毎朝はかる**

- 毎朝記録。メインは7日間の平均、当日の数字は小さく表示
- 進捗判定と月末の割り直しには7日間の平均を使う

## 7. AIの役割（相談のみ）

- 体重が動かない時のチェックイン相談
- 自由な質問への相談窓口
- プラン生成・リプラン・レコメンドはAIを使わない

## 8. v1から削るもの

- 細かい食事・運動ブロックの表示
- 運動前提の週間プラン
- AIによるプラン生成（/api/generate-plan）とリプラン（/api/replan）
- 週次の欲望宣言フロー

## 9. 実装の順番

**フェーズ1：毎日使える状態にする**

1. 計算ロジック（目標・ゲート・週予算・貯金ゲージ・軽め回数）を `@/lib/calories` に集約し、テストを書く
2. 初回設定（身長・体重・目標・期間 → BMI上限チェック → ゲートと1日の貯金を算出）
3. 欲望の月登録（日付指定＋週の頻度、いつでも1タップ追加）
4. 毎日の記録とホーム（目安パターン表示・3択記録・貯金ゲージ・軽めの回数）

**フェーズ2**

1. 運動アドオン（1pt = 1kcal でゲージに加算）
2. 毎朝の体重記録と7日間の平均
3. 月末の割り直し
4. 進捗チャート（7日平均の体重とゲート目標ラインを重ねて表示）

**フェーズ3**

1. AI相談（体重が動かない時のチェックイン・自由相談）
